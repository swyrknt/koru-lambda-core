# koru-lambda-core 2.0.0 — Release Checklist

This is the single source of truth for what 2.0.0 still needs. 2.0.0 ships only when every box is ticked.

> **Scope, settled 2026-09-30.** 2.0.0 publishes the substrate and nothing else:
> `koru-lambda-core`, plus `koru-lambda-wasm` — **a first-class product
> surface, not a test fixture.** It ships to npm alongside the crate.
> Accessibility is the argument: a reader reproduces a child id in a browser
> console with no toolchain at all, which is the shortest path from the claim
> to someone checking it, and a Rust-only release would confine the theory to
> people who already have a Rust toolchain. It also happens to be the second
> target that makes cross-target byte equality demonstrable rather than
> asserted. Everything below the `Not blocking 2.0.0` line stays in the
> repository and ships when it is ready.
>
> The obligation that comes with shipping it: the JS surface has to be good.
> Today a JS consumer cannot get their own data into the engine at all
> (JS-9), which makes the package a demonstration rather than a tool. What we
> do *not* take on is compatibility with v1.2's JS consumers — downstream is
> out of scope, so the surface should be right rather than backward-compatible.
>
> The number that decided it: the published v1.2.0 is 4,489 source lines, of
> which engine, primitives and lib are **409 — nine percent**. The rest is
> consensus machinery, a C ABI and bindings. Carrying that forward would have
> reproduced a crate in which the theory is a rounding error.

## Rules

1. **An unticked box blocks the release.** The release script refuses to publish while any `- [ ]` remains in this file.
2. **A ticked box needs evidence.** Every `- [x]` item must carry an `evidence:` line naming a test (`path::name`), a commit SHA, a CI run URL, or a tracked file. CI rejects ticked items with no evidence or with evidence that doesn't resolve.
3. **Evidence is shown, not claimed.** "Tests pass" is not evidence. The specific test or command that would fail if the item regressed is. An item whose evidence can only be a human opinion is written wrong; rewrite it until a command can fail.
4. **Zero warnings, zero suppression.** No `#[allow]`, `#[expect]`, lint relaxations, `@ts-ignore` or `eslint-disable` anywhere — and no suppression by configuration either (`clippy.toml`, `[lints]`, tool config). Fix the cause.
5. **Nothing is deferred.** Items do not move to a later version. If an item is wrong, it is corrected or removed in a reviewed change, with the reason stated inline.
6. **Decisions are items too.** `DEC-*` items are open questions for the owner; they block like any other item. A decision is closed by a written outcome naming its `docs/SPEC.md` section ("accepted, see SPEC §X") or the item that implements the change ("changed, see ITEM-N"), never by silence.
7. **Findings become items.** Anything a review, mutation run, probe or downstream check turns up is added here as a numbered item before that gate can be ticked. This file is expected to grow during the work; a run that adds nothing is evidence the gate wasn't applied honestly.

Item format:

```
  - [ ] AREA-N Short statement of the required end state
    - evidence: <test path::name | commit | CI run | file>
```

(Indented above so the gates do not read the template as a real item.)

`file:line` references in item text describe the state found on 2026-09-21 and are not live claims; they locate the thing to fix, and go stale once the item is done or the workspace split moves the file. Evidence lines, by contrast, must resolve at the time the box is ticked.

## What this crate is (review finding, 2026-09-21)

Five independent reviews, forbidden from looking at downstream usage, agreed on the boundary:

> **koru-lambda-core is the content-addressed graph produced by one commutative irreflexive operator, every read of that graph the axioms force, and the lift that gets outside values into it — and nothing that requires knowing about peers, actors, transactions or time.**

The criterion used: an item belongs in the substrate if deleting it would leave an axiom or law with no referent in the crate. By that test the validator, commitment, network, compactor and batch modules are *reference consumers*, not substrate — which `ARCHITECTURE.md` already states ("These are not the substrate — they USE it") and `src/subsystems/mod.rs` says outright, while `Cargo.toml` and packaging say otherwise.

Three objects are constitutive: **witness** (engine + verify), **vantage** (projection), **lift** (`Canonicalizable`, `ByteMapping`, the anchored fold). The lift is the substrate's only free parameter and is currently its thinnest layer: one stdlib impl (`u8`), no public fold, nothing exposed to JS, no example. Two in-crate consumers hand-rolled the same fold privately and both got the anchor wrong — which is the collision bug.

**Settled 2026-09-21.** Placement (DEC-9): four crates — `koru-lambda-core`, `koru-lambda-agents`, `koru-lambda-wasm`, `koru-lambda-ffi` — one workspace, one release, one bar (PKG-1..7). Extensibility (DEC-10): `ReadOnlyEngine` unseals so alternative engines remain possible; `CoreSignal` stays sealed; `Boundary`/`Direction` stay closed (SEAL-1..3). Nothing is dropped.

## FRZ — The freeze (identity cannot move; found 2026-10-01)

`ECOSYSTEM.md` promises "identity never moves ... for the life of the major
version". Nothing enforces that today. `api/*.txt` records `pub const
vectors::C_HEX: &str` — the **type**, not the value — so editing a vector
leaves the snapshot byte-identical; `cargo-semver-checks` is a shape tool and
`.github/workflows/ci.yml` declares it a no-op against a 1.2.0 baseline that
has no `vectors` module; and `src/vectors.rs` ships *inside* the crate it
pins, so one commit can change `synth_bytes` and regenerate the vectors
together with every job green. A conformance suite that lives inside the
implementation certifies internal consistency and nothing else. This is the
third instance of the release's root cause — a check that exists and does not
check — and the first one that sits under a published guarantee.

## CONF — Conformance (the polyglot mechanism, settled 2026-10-01)

The strategy, recorded in `ECOSYSTEM.md`: the substrate's algorithm is small
enough that a conforming implementation is tens of lines in any language, so
a *conformance suite* reaches more languages than bindings do, at a fraction
of the cost. These items are what make that claim true rather than stated. A

# Not blocking 2.0.0

## EMG — The emergence ladder *(research; nothing here blocks 2.0.0)*

`THEORY.md` makes a **framework** claim and stakes it on fertility. This
section is where that claim is turned into experiments, under the rules in
`ROADMAP.md` § Research, and where it belongs. Every item needs a null model
stated before it runs, because this project has twice measured its own harness
and reported the result as the substrate's.

- [x] EMG-1 Does anything scale-invariant appear under a draw policy that encodes **nothing**? Prediction stated before measurement: the global mean clustering figure observed in passing is the *policy's*, not the substrate's, and should fall as ~1/N under uniform pairing because two distinctions drawn from a pool of size N are adjacent with probability ~4/N.
  - evidence: `experiments/runner/src/emergence_probe.rs`, run via `cargo run -p koru-experiments-runner --release --bin emergence_probe`. **Prediction confirmed, and the result bounds the emergence claim.** Over a 27× scale range (d = 489 → 13,477), two arms on the same seed:

    | | clustering | triangles | max degree |
    |---|---|---|---|
    | uniform (policy-free) | 0.005129 → **0.000347** | 19 → **30** | 21 |
    | locality-biased | 0.639 → **0.633** | 322 → 8,611 | 19 |

    Under a policy that encodes nothing the substrate produces **essentially no clustering** — it falls as ~1/d, and the absolute triangle count grows from 19 to 30 while the graph grows 27-fold, consistent with logarithmic rather than linear growth. Under locality bias clustering is stable to three decimals across the same range, which is what a *policy* constant looks like. Both arms assert `r = 2d − 3` and zero unexplained triangles as controls, so a divergence would indict the harness rather than flatter the substrate. **Now gated** by `experiments/runner/tests/emergence.rs`, because the probe is a binary that prints numbers and an ungated conclusion is the pattern this release keeps finding. Scale caveat checked: the arms are matched on *steps*, not on `d`, and the locality arm saturates more — but it spans 324 → 8,613, a 26.6× range against the uniform arm's 27.6×, so "a comparable range" is accurate where "the same range" would not be.
  - **what this means for the framework claim:** complexity does not emerge from synthesis alone. It emerges from synthesis *plus a policy that already has structure in it* — the substrate is the medium, and the policy is where the information is. That does not refute the ladder; it says each rung needs its own policy, and the real question is which policies produce which rungs. Note also that **neither** arm produced hubs: max degree 21 against a mean of 4, a thin tail and not a power law, which is independent corroboration of the Law 11 demotion and of the previous release's scale-free result having been a harness artifact.
- [x] EMG-5 **Exactly four of eighteen reads are extension-invariant.** Ancestry is fixed at creation and the graph is append-only, so an upstream read of a witnessed root cannot change however much is appended — including an unbounded one, since the complete ancestry closure of a fixed node is itself fixed. Degree grows as children appear; downstream and undirected reads rebuild their children index from the whole engine.
  - evidence: `tests/extension_invariance.rs`. Predicted before measuring, and exact: the invariant set is `Upstream` × `{Adjacency, HopDistance}` × `{hops(2), saturated}` and nothing else. The test also asserts all eighteen **projection identifiers are unchanged**, which is correct by specification — identity covers the spec, not the output — and is precisely why the published surface **cannot express this property**. It matters for anyone building a read-feeds-write loop: those four are the only reads that could drive one without the read depending on how far the graph has got.
- [ ] EMG-6 **Degree share is the substrate's one scarce quantity, and dilution is a selection mechanism append-only permits.** Law 6 pins total degree at ≈ 4d, so degree *share* is zero-sum: every novel synthesis dilutes every non-participating node. Append-only forbids death; it does not forbid **irrelevance**, and a node that stops participating decays as 1/d. EMG-1's own data is a picture of this — clustering falling as 1/d *is* dilution, and max degree 21 against a mean of 4 is a dilution-dominated regime, while the locality arm's flat 0.633 is one where participation keeps pace. This is the answer to "there is no selection pressure, so nothing can prune", which was wrong. Test: hold steps fixed, sweep policies, measure the **Gini coefficient of degree share** and the share-decay exponent for non-participating nodes against `d`. Prediction: the exponent is −1 under every policy (forced by Law 6) while the Gini is entirely the policy's. A policy-invariant Gini would be a constant nobody installed.
- [ ] EMG-7 The "agreement **or** selection" trade is restated around **retraction**, not aggregation — and the narrower door that opens is tested. A literature check located the trade as the CALM theorem (coordination-free ⟺ monotone), and corrected the reasoning: aggregation per se is *not* the dividing line. A monotone aggregate, or a threshold on one, is coordination-free — the published example is `count(*) > 1000`, confluent because counts only increase. What forces coordination is **retracting a previously emitted answer**, which is why `argmax degree` fails: adding an element can remove the old winner. So a policy reading *"any node whose degree exceeds k"* is both confluent **and** uses the one scarce quantity, where `argmax` cannot be. That breaks the dichotomy as I stated it: you cannot have agreement and *optimality*, but you may be able to have agreement and *sufficiency*. Test: run the threshold policy against the uniform null and ask whether it produces structure the policy-free arm does not, while two partial witnesses still converge. Also record the model assumption CALM's *iff* depends on — nodes knowing nothing of the distribution policy; weaker monotonicity admits larger coordination-free classes once they know more.
- [ ] EMG-8 **Confluent endogenous dynamics, tested.** The derivation: a policy expressed as a *total function* of each node's sealed ancestry — rather than a *selection* over global state — is monotone, hence coordination-free, hence Laws 8 and 9 survive. No choice, no argmax, no retraction: every node yields a successor determined entirely by data frozen at its birth. The earlier objection, that an ancestry-reading policy must still pick a root and root selection is state, dissolves because a total function makes no selection at all. Test: implement it over `Upstream`/`saturated`, run two engines seeded differently, merge, and assert the merged state is reachable and identical either way. If it converges, there is confluent endogenous dynamics and the ladder question reopens properly; if not, the premise is wrong and it matters which half. **Treat as a derivation to be tested, not a result** — three claims of this shape were wrong in the two days before it, each from an unchecked premise.
- [ ] EMG-9 *(2.1 API candidate, deliberately deferred)* A marker trait making extension-stability a **compile-time** property, so a builder chain over the stable quadrant yields a type that proves it and an agent can be typed to accept only stable specs. It would turn the discipline from documentary into enforceable, and it has no byte implications. Deferred because it fails the substrate's membership test, it is new public surface, and the surface is not settled — a dozen tracked items still change it, six of them removals. Adding API while removing API is how a crate ends up with both. Revisit once the surface stops moving, and after EMG-8, which would strengthen the case considerably.
- [ ] EMG-2 The ladder's rungs are each stated as a falsifiable prediction with the policy that is claimed to produce them. Right now the chain — distinction, information and logic, waves, atoms, physics — is unfalsifiable for a boring reason: nobody has written down what would count as a rung failing. Writing that down is the work.
- [ ] EMG-3 The known blocker is named in whatever document carries the ladder: the rungs above "order from nesting" need **dynamics**, and the substrate is timeless by design. Propagation needs time, and time is explicitly a consumer concern. This is not an oversight — timelessness is what makes Laws 8 and 9 hold, so adding dynamics to the substrate trades away convergence-without-coordination. Any ladder that reaches waves has to say what it is giving up. **And the obvious escape does not work.** Coupling the synthesis/projection dual so that a read feeds the next write — making iteration itself the clock — does not buy dynamics for free: a draw policy is either state-independent, in which case it is exogenous input and nothing is closed, or state-dependent, in which case two engines with differing witnessed sets produce divergent write streams. There is no third option, so Laws 8 and 9 do not survive the loop — they become **inapplicable**, being claims about a given operation stream that a closed loop no longer has. Nor is Law 10 already one step of such a loop: it takes a `Distinction`, whereas a read yields a map, and collapsing a map to a distinction requires the lift — the one component the theory names as free and version-unstable.
- [ ] EMG-4 A policy-free run is characterised at a scale where logarithmic and constant triangle growth can be told apart. Four points over 27× cannot distinguish `4·ln(N)` from a bounded constant, and EMG-1 deliberately claims only "far slower than linear".

Retained in the repository, out of the release. Nothing here is abandoned; it is unscheduled.
